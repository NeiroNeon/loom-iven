# Публикация репозитория на GitHub — пошагово

Репозиторий полностью готов к push: чистая история (коммит v1.8.0 + релиз-коммит v1.8.1
с тегом), секреты вычищены, тяжёлые архивы вынесены в Release. Осталось выполнить шаги ниже.

## 0. Что где лежит

| Что | Где | Куда на GitHub |
|---|---|---|
| Код, конфиги, сайт, доки | этот каталог (git, ветка `main`, тег `v1.8.1`) | git push |
| Единый архив релиза (~281 МБ) | `download/loom-iven-v<версия>.zip` | asset Release |

Единый архив содержит ВСЁ содержимое релиза без дублей: `server-pack/` (готов к запуску),
`loomplugin/` (исходники), `scripts/`, `site/`, `docs/`, README/STATE/VERSION/CHANGELOG.

Лимиты GitHub: файл в git — до 100 МБ (у нас максимум ~1 МБ), файл-asset Release — до 2 ГБ.

## 1. Создать репозиторий

**Через сайт:** github.com → New repository → имя `loom-iven` → Public → **без** README/
.gitignore/license (всё уже есть) → Create.

**Через gh CLI:**
```bash
gh auth login
gh repo create loom-iven --public --source=. --push
```

## 2. Запушить код

```bash
cd download/loom-iven-github
git remote add origin https://github.com/<ВАШ_НИК>/loom-iven.git
git push -u origin main --follow-tags
```

При желании переподписать автора под свой аккаунт перед push:
```bash
git commit --amend --no-edit --reset-author
git tag -fa v1.8.1 -m "Loom Iven v1.8.1" && git push -f origin v1.8.1
```

## 3. Создать Release v1.8.1 и загрузить единый архив

**Через сайт:** Releases → Draft a new release → выберите тег `v1.8.1` → заголовок
`Loom Iven v1.8.1` → текст из `docs/RELEASE_NOTES_v1.8.1.md` → перетащить
`download/loom-iven-v1.8.1.zip` → Publish.

**Через gh CLI:**
```bash
gh release create v1.8.1 \
  ../loom-iven-v1.8.1.zip \
  --title "Loom Iven v1.8.1" \
  --notes-file docs/RELEASE_NOTES_v1.8.1.md
```
(путь указан от каталога репозитория к `download/`)

## 4. Включить GitHub Pages для сайта

Settings → Pages → Build and deployment → Source: **GitHub Actions**.
Workflow `.github/workflows/pages.yml` задеплоит `site/` автоматически
(адрес: `https://<ник>.github.io/loom-iven/`), либо запустите его вручную (Actions → Deploy site).

## 5. Рекомендации по оформлению

- Description: `Кроссплатформенный Minecraft-сервер (Paper 26.3): выживание+SMP, 5 своих плагинов, GUI для Java и Bedrock, сезонный пропуск, сайт. RU/EN`
- Topics: `minecraft`, `minecraft-server`, `paper`, `spigot`, `geyser`, `floodgate`, `smp`

## 6. Будущие релизы (чтобы не «восстанавливать из прошлого патча»)

1. Разработка ведётся в рабочем дереве; после вехи: `bash scripts/mirror.sh` + коммит рабочей копии.
2. Поднять `VERSION.txt`, обновить `STATE.md` и `CHANGELOG.md` (в репозитории).
3. `bash scripts/package_single.sh` — соберёт ЕДИНЫЙ архив `download/loom-iven-v<версия>.zip`
   (server-pack + исходники + сайт + доки; заменяет прежние server-pack/sources/site.zip).
4. `LOOM_TAG=v<версия> bash scripts/publish_github.sh` — синхронизация в этот репозиторий,
   коммит и аннотированный тег (если каталог репо удалён — скрипт сам развернёт его из zip).
5. `git push origin main --follow-tags`
6. `gh release create v<версия> download/loom-iven-v<версия>.zip --notes-file ...`
7. Прежние версии архивов из `download/` удалять (история — в git-тегах и старых Release).

## 7. Чек-лист секретов (проверено перед публикацией)

- ✅ `server-configs/server.properties`: RCON-пароль и management-secret → `CHANGE_ME_*`
- ✅ `server-configs/plugins/DiscordSRV/config.yml`: `BotToken: "BOTTOKEN"` (плейсхолдер)
- ✅ `.env`, data-папки плагинов, usercache, миры — в репозиторий не входят
- Перед каждым будущим релизом прогонять:
  `grep -rn "rcon.password\|BotToken:" server-configs/ | grep -v CHANGE_ME | grep -v BOTTOKEN`
  (команда должна вывести только строки с плейсхолдерами)
